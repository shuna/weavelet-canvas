## 節約と残る失敗

長い反復T13は1696→339、T14は1121→215 input tokens（後続要求/role/共有wrapper込み、2回平均）。約80–81%削減だが通常要約312.5/178より多い。短く密なT01–T12では増えるケースが多く、一般的なトークン節約を断定できない。APIの実測はmetrics.json。UIは送信モデルの既存tokenizerによる**推定**を表示し、削減がなければ「削減なし」とする。

未使用H01の窓からの入口省略、H03の採用ラベルを実装済みへ進める応答、既存C04の回答済み質問再開、C10のユーザー口調の勝手な採用、C13のnullを項目別nullへ変更などが残る。無料モデルも敬体/常体・人物の声・不確定性の保持がモデル/設定で異なる。原文側にも追従失敗がある。個別理由はmanual-review.md、入力・出力・モデル/提供元・設定・response ID・usageはapi-results.json。

生データのjudgment欄は採点前の表示を保持し、レビュー済みの範囲・理由をmanual-review.mdに分離する。全出力への独立した意味採点、盲検、seed固定、統計的な安定性推定は行っていない。参考要約との一致や文字列テストを生成品質保証に使わない。
